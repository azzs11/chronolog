# ChronoBench: RootRank with an estimated incident start

The benchmark hands every method the true start time; a live system does not have it. Generated by `uv run bench autostart`; do not edit by hand.

## Setup

- All 359 RCAEval cases, headline protocol (whole root services held out, 5 seeds, 25 rounds); the model is trained on true-start features.
- Each held-out window is **cropped at random** to 300-720 s before and after the true start (seeded by case id). Without this, guessing the middle of the window would score perfectly, because RCAEval windows are symmetric around the start.
- **Estimated start:** the split of the window where log behaviour changes most (a Poisson likelihood-ratio statistic summed over every service and template; see `startdetect.py`). It needs at least 4 minutes of logs.
- **First-error rule:** the heuristic the API used before ('first error-level line after 20 lines'). A case where it finds no start counts as a miss.
- Offsets are detected minus true start, over the cases where a start was found.

## Results

| Incident start used | AC@3 | Start found | Median offset | Within 30 s | Within 60 s | Within 120 s |
|---|---|---|---|---|---|---|
| true start | 53.2% ± 2.4 (44-62) | 359 of 359 | +0 s | 100% | 100% | 100% |
| estimated start | 45.0% ± 2.3 (36-53) | 359 of 359 | +13 s | 32% | 39% | 55% |
| first-error rule | 31.6% ± 1.5 (21-42) | 228 of 359 | -356 s | 18% | 27% | 30% |

## What this means

- The estimator keeps most of RootRank's accuracy without being told when the incident began.
- The estimator cannot tell a calm window from an incident window (on calm windows it scores about as high), so the app asks the user, or an alert, to say that something went wrong, and estimates only the start.
