# ChronoBench: the Fault Playground's simulated incidents

How does RootRank behave on the live demo? Generated by `uv run bench playground`; do not edit by hand.

## Read this first

- The logs are written by ChronoLog's own simulator (`packages/engine/src/sim`): six services, six fault types, seeded. **This is illustrative. It is not the benchmark**; real accuracy on RCAEval incidents is in [RESULTS-rootrank.md](RESULTS-rootrank.md).
- With only 6 services, random guessing is right 17% of the time at top-1 and 50% at top-3. Compare every number below with those.
- Each row runs every observable (service, fault) pair with 20 seeds. A network delay or packet loss on the gateway leaves no logs at all, so those two combinations are not offered.

## Results

| Fault | Runs | Top-1, start given | Top-1, start estimated | Top-3, start given | Top-3, start estimated |
|---|---|---|---|---|---|
| Crash and restart (easy) | 120 | 100% | 81% | 100% | 92% |
| Disk full (easy) | 120 | 100% | 100% | 100% | 100% |
| Memory pressure (medium) | 120 | 100% | 100% | 100% | 100% |
| CPU saturation (medium) | 120 | 16% | 16% | 83% | 83% |
| Network delay (hard) | 100 | 16% | 16% | 100% | 100% |
| Packet loss (hard) | 100 | 16% | 16% | 100% | 100% |
| **All faults** | 680 | 60% | 57% | 97% | 96% |

## What this shows

- Faults that leave their own mark in the broken service's logs (a crash writes startup lines, a full disk writes errors) are found every time when ChronoLog is told when the fault began. A crash is sometimes missed when it has to estimate the start, because a brief outage can pull the estimate off.
- Faults that show up only in other services' logs (network delay, packet loss) are close to chance at top-1, though the true service usually stays in the top 3. The same pattern appears on real incidents.
