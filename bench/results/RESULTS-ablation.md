# ChronoBench: RootRank ablation and breakdowns

Which signals matter, and where does RootRank win or lose? Generated by `uv run bench ablate`; do not edit by hand.

## Setup

- Headline protocol: 5-fold cross-validation over all 359 cases, holding out whole (system, root service) groups; mean ± standard deviation over 5 seeds; 25 boosting rounds (chosen earlier on the train split, not re-tuned here).
- Cases whose root service writes no logs count as misses for every method.

## AC@3 by fault kind

RootRank solves the Train Ticket code faults perfectly. The likely reason (not verified) is that a code fault runs changed code, which logs messages the service never logged before, and the novel-template features see that at once. Resource faults leave far fewer traces in logs, and this is the harder and more honest number.

| Group | Cases | First error | ChronoLog-H | RootRank |
|---|---|---|---|---|
| code fault (f1-f5) | 90 | 50.0% | 37.8% | 100.0% |
| resource fault | 269 | 20.8% | 22.7% | 36.8% |
